## DataOps

DataOps는 애자일, DevOps, 통계적 공정 관리에서 검증된 좋은 방법을 데이터 업무에 적용해 데이터 제품을 빠르고 정확하며 안정적으로 제공하는 방식이다.

DataOps의 흐름은 다음과 같이 정리할 수 있다.

```text
데이터 코드 작성
        ↓
자동 테스트 및 품질 검사
        ↓
안전하게 배포
        ↓
데이터 제품 제공
        ↓
데이터 품질과 파이프라인 감시
        ↓
피드백 수용 및 개선
```

## 자동화

자동화는 DataOps 프로세스의 신뢰성과 일관성을 보장하는 데 도움을 준다.

반복 작업을 자동화하면 같은 절차를 일정하게 수행할 수 있으며, 데이터 엔지니어는 새로운 기능과 개선 사항을 기존 워크플로에 신속하게 반영할 수 있다.

자동 테스트와 품질 검사를 활용하면 배포 전에 오류를 발견하고 잘못된 데이터가 다음 단계로 전달되는 것을 줄일 수 있다.

## DAG

DAG는 `Directed Acyclic Graph`의 약자로, 방향성 비순환 그래프를 의미한다.

데이터 파이프라인을 구성하는 작업의 순서와 의존 관계를 화살표로 표현하며, 작업의 흐름에는 다시 이전 작업으로 되돌아오는 순환이 없다.

예를 들어 다음과 같은 ETL 작업을 DAG로 표현할 수 있다.

```text
데이터 추출 → 데이터 정제 → 데이터 변환 → 데이터 저장
```

## 관찰 가능성과 모니터링

잘못된 데이터는 바로 발견되지 않으면 이후의 분석, 의사결정, 데이터 제품에 큰 피해를 줄 수 있다.

따라서 데이터 파이프라인의 상태와 데이터 품질을 지속적으로 확인하기 위해 관찰 가능성, 모니터링, 로깅, 경고, 추적이 필요하다.

- 관찰 가능성: 시스템 외부의 정보를 통해 내부 상태와 문제 원인을 파악할 수 있는 능력
- 모니터링: 정해진 지표와 조건을 지속적으로 확인하는 활동
- 로깅: 작업 과정과 발생한 사건을 기록하는 활동
- 경고: 이상 상태가 감지되었을 때 담당자에게 알리는 기능
- 추적: 데이터와 작업이 파이프라인을 거치는 흐름을 확인하는 활동

## 사고 대응

데이터 시스템을 운영하는 과정에서 실수와 장애를 완전히 없애기는 어렵다.

자동화와 관찰 가능성을 갖추면 문제를 조기에 발견하고 원인을 빠르게 파악할 수 있다. 데이터 엔지니어는 사용자가 문제를 발견하기 전에 파이프라인과 데이터 품질을 감시해 사고를 예방하고, 사고가 발생한 경우 신속하게 대응해야 한다.

## 핵심 정리

- DataOps는 데이터 제품을 빠르고 정확하며 안정적으로 제공하기 위한 업무 방식이다.
- 자동화는 반복되는 데이터 작업의 신뢰성과 일관성을 높인다.
- DAG는 파이프라인 작업의 순서와 의존 관계를 순환 없이 표현한다.
- 관찰 가능성과 모니터링은 데이터 및 파이프라인 문제를 조기에 발견하는 데 필요하다.
- 사고 대응 체계를 갖추면 문제의 원인을 빠르게 파악하고 피해를 줄일 수 있다.
