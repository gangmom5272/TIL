# 데이터 엔지니어링 수명 주기

## 오늘 읽은 범위

견고한 데이터 엔지니어링에서 데이터 엔지니어링 수명 주기 중 수집과 변환 파트를 읽었다.

## 핵심 키워드

- 데이터 엔지니어링 수명 주기
- 데이터 수명 주기
- 원천 시스템
- 스토리지 솔루션
- 배치 수집
- 스트리밍 수집
- 데이터 수집
- 데이터 변환

## 데이터 엔지니어링 수명 주기

데이터 엔지니어링 수명 주기는 원천 시스템에서 데이터를 수집하고, 저장하고, 변환한 뒤, 분석가, 데이터 과학자, ML 엔지니어 등이 사용할 수 있도록 제공하는 것을 목표로 한다.

데이터 엔지니어링은 단순히 데이터를 옮기는 일이 아니라, 데이터가 필요한 사람에게 안정적이고 활용 가능한 형태로 전달되도록 전체 흐름을 설계하고 운영하는 일이다.

## 데이터 수명 주기와의 관계

데이터 엔지니어링 수명 주기는 데이터 수명 주기의 하위 집합이다.

데이터 수명 주기가 데이터의 생성부터 폐기까지 전체 흐름을 다룬다면, 데이터 엔지니어링 수명 주기는 그중 데이터를 수집, 저장, 변환, 제공하는 기술적 흐름에 집중한다.

## 원천 시스템

원천 시스템은 데이터가 처음 생성되는 시스템이다.

예를 들어 서비스 데이터베이스, 애플리케이션 로그, 외부 API, 이벤트 로그, 파일 등이 원천 시스템이 될 수 있다.

데이터 엔지니어는 원천 시스템에서 발생한 데이터를 안정적으로 수집할 수 있어야 한다.

## 스토리지 솔루션

스토리지 솔루션은 데이터의 종류와 사용 목적에 맞게 데이터를 저장, 조회, 보호, 관리할 수 있도록 만든 제품이나 시스템이다.

데이터의 형태와 목적에 따라 적절한 저장소를 선택해야 한다.

예를 들어 정형 데이터는 관계형 데이터베이스에 저장할 수 있고, 대용량 원천 데이터는 데이터 레이크나 오브젝트 스토리지에 저장할 수 있다.

## 데이터 수집

데이터 수집은 원천 시스템에서 데이터를 가져오는 단계이다.

수집 방식은 크게 배치와 스트리밍으로 나눌 수 있다.

## 배치 수집

배치 수집은 미리 설정된 시간 간격이나 미리 설정된 데이터 크기 임계값에 도달했을 때 데이터를 모아서 수집하는 방식이다.

예시:

- 매일 자정에 전날 주문 데이터를 수집
- 1시간마다 로그 파일을 모아서 수집
- 일정 크기 이상의 파일이 쌓이면 한 번에 처리

배치 방식은 실시간성이 낮아도 되는 데이터 처리에 적합하다.

## 스트리밍 수집

스트리밍 수집은 데이터가 생성되는 즉시 또는 거의 실시간으로 데이터를 수집하는 방식이다.

예시:

- 사용자 클릭 이벤트 실시간 수집
- 실시간 로그 처리
- 실시간 결제 이상 탐지

스트리밍 방식은 빠른 반응이 필요한 서비스나 실시간 분석에 적합하다.

## 배치와 스트리밍 비교

| 구분 | 배치 | 스트리밍 |
|---|---|---|
| 처리 방식 | 일정 시간이나 크기 단위로 모아서 처리 | 데이터가 발생하는 즉시 처리 |
| 실시간성 | 낮음 | 높음 |
| 예시 | 일별 매출 집계, 정기 리포트 | 실시간 로그, 클릭 이벤트, 이상 탐지 |
| 장점 | 구조가 비교적 단순하고 관리가 쉬움 | 최신 데이터를 빠르게 활용 가능 |
| 단점 | 최신 데이터 반영이 늦을 수 있음 | 설계와 운영이 더 복잡할 수 있음 |

## 데이터 변환

데이터 변환은 수집한 데이터를 사용 목적에 맞게 정리하고 가공하는 단계이다.

변환 과정에서는 데이터 타입을 맞추거나, 필요한 컬럼만 선택하거나, 잘못된 값을 정리하거나, 여러 데이터를 조합해 새로운 값을 만들 수 있다.

예시:

- 날짜 형식 통일
- NULL 값 처리
- 중복 제거
- 필요한 컬럼만 선택
- 금액, 수량을 이용해 총액 계산
- 분석용 테이블로 재구성

## 오늘 배운 점

데이터 엔지니어링 수명 주기는 원천 시스템에서 데이터를 가져와 저장하고 변환한 뒤, 데이터를 필요로 하는 사람들에게 제공하는 흐름이다.

수집 방식에는 배치와 스트리밍이 있으며, 데이터의 사용 목적과 실시간성 요구에 따라 적절한 방식을 선택해야 한다.

데이터 변환은 수집한 데이터를 분석과 활용에 적합한 형태로 바꾸는 과정이며, 앞으로 ETL 실습에서 직접 다루게 될 핵심 단계이다.
