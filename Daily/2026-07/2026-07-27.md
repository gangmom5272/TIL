데이터 엔지니어링 수명 주기는 데이터의 생성부터 폐기까지를 다루는 데이터 수명 주기의 하위 집합이다.

### 배치와 스트리밍

배치는 미리 정한 시간 간격이나 데이터 크기 임계값에 도달했을 때 데이터를 모아서 처리하는 방식이다.

스트리밍은 데이터가 생성되는 즉시 또는 거의 실시간으로 데이터를 처리하는 방식이다.

데이터의 사용 목적과 필요한 실시간성에 따라 적절한 수집 방식을 선택해야 한다.

## SQL

### 오늘 푼 문제

1. 어린 동물 찾기
2. 아픈 동물 찾기

두 문제 모두 `WHERE`절로 특정 조건에 해당하는 행을 조회하고, `ORDER BY`로 결과를 정렬하는 기본 문제였다.

```sql
SELECT ANIMAL_ID, NAME
FROM ANIMAL_INS
WHERE INTAKE_CONDITION != 'Aged'
ORDER BY ANIMAL_ID;
```

```sql
SELECT ANIMAL_ID, NAME
FROM ANIMAL_INS
WHERE INTAKE_CONDITION = 'Sick'
ORDER BY ANIMAL_ID;
```

어렵지 않게 풀었으며, `=`와 `!=`를 사용한 조건 조회를 복습했다.

## ETL Practice

### Mission 01 - CSV 주문 데이터 정제

주문 원본 CSV 파일을 읽고, 취소된 주문을 제거한 뒤, 주문별 총금액을 계산해 새로운 CSV 파일로 저장했다.

### Extract

파이썬의 `csv.DictReader`를 사용해 `orders_raw.csv`를 읽었다.

CSV에서 읽은 각 행은 컬럼명을 키로 갖는 딕셔너리 형태이며, 읽은 값은 기본적으로 문자열이라는 점을 배웠다.

### Transform

- `status`가 `canceled`인 주문 제거
- `price`와 `quantity`를 `int`로 변환
- `price * quantity`로 `total_price` 계산
- 정상 주문 4건만 결과에 포함

### Load

`csv.DictWriter`를 사용해 정제된 주문 데이터를 `orders_clean.csv`로 저장했다.

저장할 컬럼과 순서를 `fieldnames`로 지정하고, `writeheader()`로 헤더를 작성한 뒤 `writerows()`로 여러 행을 저장했다.

### 오늘 이해한 ETL 흐름

```text
orders_raw.csv 읽기
        ↓
취소 주문 제거 및 총금액 계산
        ↓
orders_clean.csv 저장
```

- Extract: 원본 CSV 읽기
- Transform: 취소 주문 제거 및 총금액 계산
- Load: 정제 결과를 새로운 CSV로 저장
